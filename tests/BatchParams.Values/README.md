# Значения пакетных параметров в семействе

Проверки используют настоящий `BatchFamilyValueWriter` и `BatchParamsModels`,
но заменяют Revit API небольшим тестовым двойником. Revit и модели не запускаются.
Это проверка логики записи, а не подтверждение работы в реальном `.rfa`.

## Воспроизводимые ошибки прежнего кода

- Без текущего типоразмера не работали ни назначение формулы, ни резервная запись.
  Исключения подавлялись, поэтому операция могла сообщить об успехе.
- Скрытая формула пресета имела приоритет над отредактированным значением.
- Тип значения определялся по текстовой подсказке, а резервная числовая запись
  использовала `double` даже для целого числа и не учитывала единицы документа.

Теперь литералы записываются подходящим перегруженным `FamilyManager.Set` во все
типоразмеры. При необходимости создаётся «Тип 1», прежний активный тип восстанавливается.
Формулы вводятся с `=`; прежние числовые выражения без префикса также поддерживаются.
Пустая ячейка не меняет значение, `""` очищает текст. Введённый литерал снимает старую
формулу. После регенерации проверяется запись; ошибки приводят к откату пакета.
Определения всех параметров создаются до назначения формул.

## Запуск

Из корня репозитория, при установленном .NET SDK и .NET Framework 4.8 targeting pack:

```powershell
dotnet restore tests/BatchParams.Values/BatchParams.Values.csproj --configfile tests/BatchParams.Values/NuGet.Config -p:AutomaticallyUseReferenceAssemblyPackages=false
dotnet run --project tests/BatchParams.Values/BatchParams.Values.csproj -c Release -f net48 --no-restore -p:AutomaticallyUseReferenceAssemblyPackages=false
dotnet run --project tests/BatchParams.Values/BatchParams.Values.csproj -c Release -f net8.0 --no-restore -p:AutomaticallyUseReferenceAssemblyPackages=false
```

39 проверок на каждой платформе: отсутствие типоразмеров, несколько типоразмеров,
текст, целые, Да/Нет, числа и единицы, формулы, JSON/CSV-пресеты, отклонённые записи,
усечение текста, ошибки и восстановление текущего типа.

Отдельная проверка компиляции движка, моделей данных и записи с установленным API Revit 2023:

```powershell
dotnet build tests/BatchParams.Api2023/BatchParams.Api2023.csproj -c Release --configfile tests/BatchParams.Values/NuGet.Config
```

При другом расположении API передайте `-p:RevitApiPath=.../RevitAPI.dll`.
Эта сборка также не запускает Revit. Результат 2026-11-16: 0 ошибок, 0 предупреждений.
Полный плагин собран для net48 и net8.0-windows с существующими предупреждениями.

`tests/Revit2024/BatchParamsSmoke.cs.txt` обновлён под запись значений вместо
константных формул. В этой задаче он **не запускался**: для интеграционной проверки
потребуется отдельная тестовая модель. Тестовые двойники не проверяют настоящую
грамматику формул, парсер единиц Revit и транзакционный откат движка Revit.

Исправление включено в подготовку выпуска 2.4.28 на базе актуального main.
Проверка не устанавливает плагин и не изменяет модели.
