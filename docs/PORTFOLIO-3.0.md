# Переработка BimboClub 3.0

Рабочая версия подготовлена на базе BimboClub Tools 2.4.32. Для инвентаризации
использованы регистрации ленты, пользовательские сценарии в коде команд,
проекты решения и механизм доставки в BimboClub Manager.

## Решения по линейке

| Сценарий | Что делает сейчас | Решение |
| --- | --- | --- |
| Схемы, виды и марки | Создание 3D-схем по системам, авторасстановка марок, перенос фильтров | В одной группе «Схемы и виды». «Копировать фильтры» переносит фильтры между видами и шаблонами текущего проекта. Для параметрических фильтров и фильтров выбора доступны перенос графики, видимости и состояния «Включён», а также перезапись настроек и копирование в назначенные шаблоны. |
| Области подрезки | Область подрезки, быстрая подрезка 2D и 3D-сечение по двум точкам | Сохранить отдельные способы выбора геометрии. Кандидат на объединение в одной панели с режимами 2D и 3D. |
| Отверстия | Задания на отверстия, расстановка в стенах/перекрытиях, ручное и пакетное объединение | Общая группа «Отверстия». Сохранены тип конструкции и способ запуска. В следующих изменениях объединять формы и расчёт после проверки различий между активным документом и связанными моделями. |
| Сети | Трассировка, соединение, выравнивание, расстояния, стояки и распределение элементов по сети | Сохранить точные действия. «Подключение труб» и «Соединить коннекторы» требуют проверки на одной модели перед объединением: команды имеют разные сценарии подбора и присоединения. |
| Крепёж, уровни и координаты | Расстановка крепежа и хомутов, привязка элементов к уровням, базовый уровень, импорт XYZ | Крепёж и хомуты потенциально можно свести в один интерфейс с профилями. Привязку выбранных элементов и настройку базового уровня держать отдельными действиями. |
| Помещения и расчёт | Пространства по связанной архитектурной модели и расчёт теплопотерь | Оба сценария сохраняются. Повторный вход в «Пространства по АР» убран. Теплопотери остаются отдельным расчётом. |
| Параметры и семейства | Правила заполнения, пакетные параметры, параметры семейств, переименование, копирование по системам, создание из DXF | Оставлен один вход в «Редактор правил». Пакетное создание параметров и изменение значений существующих параметров имеют разные задачи. DXF остаётся отдельной командой. |
| Листы и обмен | Печать, пакет спецификаций, немоделируемые дополнения, JSON, Excel, копирование листов и элементов, шрифты и размеры | «Допы в спеку» оставлены в меню выпуска данных. Экспорт Excel и импорт таблиц сохраняют свои сценарии. Копирование листов и копирование элементов разделены по объекту операции. |
| Revit Server | Вход из Revit, отдельное приложение, мост и установщик | Единый знак и палитра оболочек. Загрузка данных Revit Server и доставка пакетов дополнения остаются разными операциями. |
| Обновления | Обнаружение Revit, чтение манифеста, получение архива, установка по версиям Revit | Заменена установка поверх действующих DLL на отдельные каталоги. Убраны окно блокировки и управление процессами Revit из сценария обновления. |

Три снятые кнопки были вторыми входами в существующие команды. Для остальных
объединений сначала нужны контрольные модели и наборы данных по сценариям.
Идентификаторы зарегистрированных команд перечислены в инвентаре ленты.

## Оформление

Графитовый фон, мягкие границы и приглушённый розовый акцент применены к
менеджеру, WPF-окнам инструментов и оболочке Revit Server. Знак BC используется
в менеджере, установщике, серверном приложении и основных окнах инструментов.
Исходник знака и экспорт размеров находятся в `tools/RenderBrandMark.ps1`.
Для 46 команд и 7 раскрывающихся меню ленты подготовлены отдельные пиктограммы в размерах 16 и 32 px. Тот же бордовый
фон и светлые линии связывают набор со знаком BC. Исходник и экспорт находятся
в `tools/RenderRibbonIcons.ps1`. Сложные окна из унаследованных модулей
требуют отдельной переработки компоновки и проверки состояний.

## Установка и переключение

1. Менеджер проверяет версию и целевую платформу сборки из архива. Пакет
   сохраняется отдельно для каждой установленной версии Revit. Стартовый
   манифест переключается после завершения копирования. Отмена или ошибка
   записи сохраняют прежний манифест.
2. При первом переходе с 2.x требуется обычный перезапуск Revit. Локальный
   менеджер может подготовить пакет при работающем Revit.
3. Начиная с версии, содержащей обработчик обновления, Revit в режиме Idling
   проверяет стартовый манифест. Более новая сборка с отдельным именем
   подключается через временную регистрацию с уникальным AddInId. Новые
   панели готовятся скрытыми. После подтверждения готовности они показываются,
   а старые скрываются.
   Подпиской на Idling владеет поколение, запущенное при старте Revit.
   Загруженные в сеансе версии передают ему свои панели. Revit запрещает
   менять подписку во время обработки Idling, и повторная подписка
   в этом месте прерывает запуск новой версии.
4. При отказе загрузки текущая панель остаётся доступной. Причина записывается
   в журнал, а установленная версия доступна при обычном следующем запуске.
5. При успешном старте нового поколения старые панели отсутствуют. Менеджер
   установки и очистка используют общий файловый замок. Revit очищает
   каталоги прошлых поколений, когда работает один процесс и файл поколения
   свободен. Файлы старой установки 2.x остаются в прежнем каталоге как резерв
   миграции.

Пакеты 3.0.0 и 3.0.1 предназначены для проверки механизма. Публичный выпуск
3.0.2 включает единое копирование фильтров и новый набор пиктограмм.
Для воспроизведения проверки механизма используйте локальный менеджер. В настройках задайте
манифест 3.0.0, установите и запустите тестовый Revit. Затем укажите манифест
3.0.1 и обновите при открытом Revit. Проверьте старую кнопку до переключения,
новую кнопку после переключения и повторный старт. Прогоните это отдельно
в Revit 2023 и 2025/2026, включая окна с WPF, отказ загрузки, несколько
процессов и проект с незавершённым редактированием.
