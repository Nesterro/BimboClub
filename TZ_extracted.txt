1. ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
2. Разработка плагина для Revit: Автоматизация подготовки данных для расчета теплопотерь
3. 1. Общее описание и цель
4. Необходимо разработать плагин для Autodesk Revit (C#, .NET, Revit API), который автоматизирует подготовку модели к расчету теплопотерь. Суть работы плагина: На основе архитектурных «Помещений» (Rooms) создаются аналитические «Пространства» (Spaces). Внутри каждого Пространства плагин анализирует граничные элементы (ограждающие конструкции) и размещает семейства «Обобщенной модели» (кубики-маркеры). Количество кубиков равно количеству ограждающих конструкций. В параметры каждого кубика записываются физические и геометрические данные соответствующей конструкции для последующего вывода в Спецификацию.
5. 2. Стек технологий и окружение
6. Язык: C#
7. Фреймворк: .NET Framework 4.8 (или .NET 8.0 в зависимости от версии Revit, указать целевую версию, например, Revit 2024+).
8. API: Revit API (Autodesk.Revit.DB, Autodesk.Revit.DB.Mechanical).
9. UI: WPF (для окна настроек/прогресса) или стандартное TaskDialog для минимального интерфейса.
10. 3. Требования к семействам и Параметрам
11. Плагин должен работать с заранее подготовленным семейством Обобщенной модели (Generic Model) HeatLoss_Cube.rfa (или создавать его/загружать из шаблона).
12. 3.1. Типоразмеры семейства (Family Symbols): Семейство должно иметь типы (или один тип с переключаемыми параметрами), соответствующие категория ограждений:
13. Cube_Wall (Наружная стена - НС)
14. Cube_Door (Дверь - ДВ)
15. Cube_Window (Окно - ОК)
16. Cube_Floor (Плита перекрытия / Пол - ПЛ)
17. Cube_Roof (Крыша / Покрытие - ПР)
18. Примечание для ИИ: Если семейство одно, использовать параметр «Категория ограждения» для фильтрации в спецификации.
19. 3.2. Общие параметры (Shared Parameters) семейства: В семействе должны быть зарегистрированы следующие Общие параметры (группа HL_ - Heat Loss):
20. HL_Element_Id (Integer) — ID элемента-хозяина в Revit.
21. HL_Element_Category (Text) — Категория (Стена, Дверь, Окно, Перекрытие).
22. HL_Area (Area) — Площадь конструкции (м²).
23. HL_Orientation_Azimuth (Angle) — Азимут ориентации (0-360 градусов).
24. HL_Room_Name (Text) — Имя помещения, к которому относится.
25. HL_Room_Number (Text) — Номер помещения.
26. HL_Is_External (Yes/No) — Является ли конструкция наружной.
27. 4. Архитектура и Алгоритм работы (Логика для ИИ)
28. Плагин должен выполняться по следующему пошаговому алгоритму:
29. Шаг 1: Инициализация и очистка
30. Открыть транзакцию (Transaction).
31. Найти в документе все существующие экземпляры семейства HeatLoss_Cube и удалить их (чтобы избежать дублей при повторном запуске).
32. Найти все существующие Space (Пространства), привязанные к Room (Помещения), и удалить их (или обновить, если они уже существуют, но безопаснее пересоздавать).
33. Шаг 2: Создание Пространств (Spaces) по Помещениям (Rooms)
34. Получить все Room в активном документе (или в выбранном пользователем Фазе/Дизайн-опции).
35. Для каждого Room:
36. Проверить, что помещение замкнуто (Room.IsEnclosedWithRoomBounding == true и нет ошибок геометрии).
37. Получить точку вставки (центр помещения или центр ограничивающего бокса).
38. Создать Space на уровне помещения, используя doc.Create.NewSpace(room, locationPoint). Примечание: для создания Space может потребоваться MechanicalSettings или привязка к фазе.
39. Шаг 3: Анализ ограждающих конструкций (Boundary Segments)
40. Для каждого созданного Space (или исходного Room):
41. Получить граничные сегменты: IList<IList<BoundarySegment>> boundaries = room.GetBoundarySegments(new SpatialElementBoundaryOptions()).
42. Настроить SpatialElementBoundaryOptions:
43. SpatialElementBoundaryLocation = SpatialElementBoundaryLocation.Finish (или Center, в зависимости от стандарта, указать в настройках плагина).
44. StoreFreeBoundaryElements = false.
45. Шаг 4: Размещение кубиков и заполнение параметров
46. Для каждого BoundarySegment в цикле:
47. Получить элемент: Element elem = doc.GetElement(segment.ElementId).
48. Определение категории и типа кубика:
49. Если elem — Стена (OST_Walls): проверить, является ли она наружной (параметр Function == Exterior или Function == Exterior-Insulation).
50. Если elem — Дверь (OST_Doors), Окно (OST_Windows), Перекрытие (OST_Floors), Крыша (OST_Roofs).
51. Важно: Если сегмент возвращает Стену, но в стене есть Двери/Окна (встройки/Inserts), плагин должен получить эти встройки через wall.Inserts и создать для них отдельные кубики (так как у них другая площадь и теплопроводность).
52. Расчет площади (HL_Area):
53. Для стен/окон/дверей: получить чистую площадь (за вычетом встроек, если это стена, или полную площадь встройки). Использовать FamilyInstance.GetGeometryObjectFromReference или HostObject.GetElementsFromReference для точного расчета, либо упрощенно через BoundingBox и габариты.
54. Для перекрытий: площадь сегмента (может потребоваться расчет площади полигона сегмента, если это часть помещения, либо площадь всего перекрытия, если оно целиком является границей. Рекомендация для ИИ: использовать площадь помещения, если перекрытие является нижней/верхней границей, либо площадь самой конструкции).
55. Расчет ориентации (HL_Orientation_Azimuth):
56. Для вертикальных конструкций (Стены, Двери, Окна): получить вектор нормали грани или вектор ориентации элемента (FamilyInstance.FacingOrientation или нормаль стены). Перевести вектор в азимут (0° - Север, 90° - Восток и т.д.).
57. Для горизонтальных (Перекрытия, Крыши): записать как "Горизонтально" или рассчитать угол наклона.
58. Размещение семейства:
59. Определить точку вставки внутри Space. Чтобы кубики не пересекались, размещать их по вертикали (стопкой) или по сетке в центре помещения.
60. Создать FamilyInstance с выбранным FamilySymbol.
61. Запись параметров:
62. Записать рассчитанные значения в параметры HL_... созданного экземпляра семейства.
63. Шаг 5: Создание Спецификации (Опционально, но желательно)
64. Проверить, существует ли Спецификация (ViewSchedule) для этих кубиков.
65. Если нет, создать новую спецификацию по категории OST_GenericModel.
66. Добавить фильтры (если используется параметр категории) и поля (столбцы) из HL_ параметров.
67. 5. Обработка граничных случаев (Edge Cases)
68. ИИ-агент должен предусмотреть обработку следующих ситуаций:
69. Помещение не ограничено: Пропускать такое помещение, выводить предупреждение в лог.
70. Отсутствует семейство HeatLoss_Cube: Плагин должен либо попытаться загрузить его из заданного пути, либо выдать понятную ошибку и прервать выполнение.
71. Перекрытия как границы: Если границей является перекрытие, GetBoundarySegments может не вернуть его напрямую. Необходимо проверить Room.LimitOffset и геометрию, либо использовать Room.GetBoundarySegments с опциями, включающими перекрытия.
72. Дубликаты: При повторном запуске плагин не должен создавать двойники. Шаг 1 (очистка) обязателен.
73. Совпадение координат: Кубики не должны пересекаться с геометрией стен (вызывает предупреждения Revit). Размещать их строго внутри объема Space.
74. 6. Интерфейс пользователя (UI)
75. При запуске команды плагина должно открываться небольшое окно (WPF):
76. Кнопка «Запустить расчет»
77. Чекбокс: «Удалять старые кубики перед расчетом» (по умолчанию true).
78. Выпадающий список: Выбор Фазы (Phase) для расчета.
79. Выпадающий список: Выбор уровня детализации границ (Core / Finish).
80. Прогресс-бар с отменой операции.
81. 7. Ожидаемый результат от ИИ-агента
82. В ответ на данное ТЗ ИИ-агент должен предоставить:
83. Полный, скомпилируемый код плагина на C# (классы ExternalCommand, IExternalApplication).
84. Код WPF окна (XAML + C# code-behind).
85. Инструкцию по созданию семейства HeatLoss_Cube.rfa и добавлению в него Общие параметров (Shared Parameters) через API или вручную.
86. Файл .addin для регистрации команды в Revit.
87. Комментарии в коде, объясняющие сложные моменты API (особенно работу с BoundarySegment и расчетом азимута).
